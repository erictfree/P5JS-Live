p5js.live

Write JavaScript and p5.js code that becomes the performance.

A browser-based instrument for improvising audio-reactive graphics: edit code without stopping the show, build scenes out of small visual patches, layer in shaders, and pass live visuals between performers.

Built by Eric Freeman at the University of Texas at Austin.

01 — LIVE EVALUATION

Change code while the performance keeps running.

Put your cursor in a patch and run it — the new version takes over immediately, no stop-build-reload cycle. If a patch fails, the last working version keeps playing, so you can experiment on stage without breaking the piece.

function ripple({ time, audio }) {
  const r = 60 + sin(time * 1.5) * 24
           + audio.bass * 140;
  circle(width / 2, height / 2, r);
}
02 — NO NEW LANGUAGE

It's still the p5.js you already know.

Write ordinary p5 calls — circle(), fill(), noise(), width, height — alongside regular JavaScript functions, objects, and classes. p5js.live just wraps a live-performance layer around the sketch you'd already build.

03 — AUDIO REACTIVE

Let sound drive the visuals.

Every patch can read live audio: overall level, bass/mid/treble energy, beat detection, FFT spectrum, and waveform data. Use the continuous values for motion and distortion, and beats for triggers and transitions — from a file, the microphone, or no audio source at all.

const size = 40 + audio.bass * 200;
const flash = audio.beat ? 255 : 20;
04 — PATCHES & SCENES

Build performances out of small, reusable pieces.

A patch is one small visual behavior. A scene is just an ordered list of patches. Add, remove, reorder, or rewrite them while the scene keeps running — and grow a personal library of patches you can drop into any future performance.

const scene = [background, scope, rings, plasma];
activate(scene);
05 — SHADERS

Go beyond the canvas.

A shader chain reprocesses the pixels a scene has already drawn: blur, bloom, split color, mask, blend, or feed the frame back through itself, all with parameters that can move with time or audio. A chain slots into a scene just like any other patch.

const lens = new ShaderChain()
  .bloom(({ audio }) => 0.2 + audio.bass, 4)
  .rgbSplit(({ audio }) => audio.treble * 10)
  .blend("screen");
06 — NETWORKED PERFORMANCE

Perform together, over the network.

Publish a canvas's output and it becomes a live source for other performers in the same room. They can layer it, transform it, or feed it into their own shader chains — sharing the visual output itself, not the code behind it. Several people can build one distributed visual system from separate browsers.

07 — DESIGNED FOR LIVE CODING

Built for changing code in front of an audience.

Live evaluation

Run one patch or the whole editor without restarting the performance.

Failure recovery

Safe state

Capture a working performance and return to it instantly.

Patch library

Install reusable patches and drop them straight into scenes.

Persistent state

Audience view

Send visuals to a clean presentation window, editor hidden.

OPEN SOURCE

Open source, built to be shared.

For creative coders, visual artists, musicians, students, and VJs — anyone who'd rather perform with code than render something and play it back. No prior live-coding experience needed — a little JavaScript or p5.js is enough to get going.
